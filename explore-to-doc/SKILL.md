# 探索过程落档（Doc）

## 何时启用

满足任一条件时启用本技能：

- 为回答问题需要搜索/阅读 **≥5 个文件**，或跨越 **≥2 个目录/模块**
- 探索路径出现分支（多处候选、多次排除、对比方案）
- 结论依赖链路追溯（调用链、配置来源、数据流）
- 用户明确要求「整理探索过程 / 写入 Doc / 记录排查过程」

简短跟进、单文件小改、已知路径的直接编辑：**不启用**。

## 落档时机

1. **探索中途**：关键发现已成型、但任务尚未结束 → 先写/更新 Doc，再继续实现。
2. **探索结束**：已得出可用结论、准备交付答案或动手改代码之前 → 必须落档。
3. **同一主题续探**：追加写入同一文档的「续探」小节，勿另起无关散文件。

## 保存位置与命名

- 目录：工作区根目录下的 `Doc/`（不存在则创建）
- 格式：Markdown（`.md`）
- 文件名：`YYYY-MM-DD-<简短主题kebab-case>.md`
  - 例：`2026-08-10-auth-token-refresh-flow.md`
- 若同日同主题已有文件：更新该文件，不新建重复文档

优先写项目根 `Doc/`。若仓库已有约定文档目录且用户指定，按其指定路径；否则仍用 `Doc/`。

## 文档结构（必须）

```markdown
# <探索主题>

- 日期：YYYY-MM-DD
- 问题：<用户原问题的一句话复述>
- 状态：进行中 | 已结论

## 目标
<本次探索要回答什么>

## 探索路径
1. <做了什么> → <关键线索 / 排除项>
2. ...

## 关键发现
- **<发现>**：依据（路径、符号、行为）
- ...

## 结论
<可执行结论；不确定处明确标注>

## 仍开放的问题
- <可选；无则写「无」>

## 相关路径
- `path/to/file` — 简述角色
```

## 写作要求

- 记「过程与依据」，不是聊天记录全文；不粘贴大段无关代码
- 路径用仓库相对路径；结论与证据对应
- 失败尝试与排除项要写清，避免后人重复踩坑
- 落档后在回复中告知用户：文档路径 + 一句话摘要

## 与其它技能的关系

- `memory-skill`：对话级关键词总结 → `talk_summary.md`
- 本技能：单次/专题探索过程 → `Doc/*.md`
- 二者可同时存在，勿互相替代
