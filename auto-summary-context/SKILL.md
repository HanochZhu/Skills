# 自动压缩 Context

## 触发时机

**每次用户提出新问题或新任务时**，在读取文件、搜索代码、调用工具之前，先评估当前 context 用量。

新问题包括：切换话题、开启独立子任务、在长对话中提出与上文无关的新需求。

## 判断用量

优先使用可见的 context 指标（按优先级）：

1. **Status line / UI 显示**：`used_percentage` 或「剩余 context %」
2. **系统提供的 context 统计**：`total_input_tokens / context_window_size`
3. **启发式**（无精确数字时）：对话轮次很多、大量 tool 输出、多文件长 diff 已堆积

计算方式：`用量 = used_tokens / context_window_size`，或 `用量 = 100% - remaining_percentage`。

## 压缩条件

当 **context 用量 ≥ 70%** 时，**必须先压缩，再开始处理新问题**。

## 压缩动作

1. 告知用户：context 已超 70%，正在自动压缩以释放空间。
2. 调用 **`/summarize`** 压缩对话历史（Cursor 内置命令）。
3. 压缩完成后，简要确认已释放 context，再继续执行用户的任务。
4. 同一轮对话中只自动压缩 **一次**；压缩后若仍 ≥70%，告知用户并建议开新会话或手动清理附件。

## 不压缩的情况

- 用量 < 70%
- 当前消息是对进行中任务的简短跟进（同一问题上下文仍必要）
- 用户明确说「不要压缩 / 保留完整历史」

## 示例

**用量 82%，用户问新问题：**

```
Context 已用 82%（超过 70% 阈值），先压缩历史…
→ 执行 /summarize
→ 压缩完成，继续处理你的问题。
```

**用量 45%，用户问新问题：**

直接开始处理，不压缩。
